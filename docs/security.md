# 보안

## 인증과 인가 모델
- 사용자 계정과 역할은 없다. 외부에서 들어오는 문은 `/api/admin/rag/**`의 관리자 POST뿐이고, `EvaluationSecretFilter`가 헤더 `X-Evaluation-Secret`과 설정 `evaluation.secret`을 비교해 막는다. 
- 시크릿을 아는 호출자는 모든 관리 기능을 쓸 수 있다.

## 비밀 값 취급 정책
- 비밀 값은 GitHub Secrets에 저장하고, GitHub Actions의 `deploy.yml`이 Cloud Run에 주입한다. 이 저장소의 코드, 문서, 로그, 작업 보고에 값을 쓰지 않는다.
- `evaluation.secret`에는 기본값이 없다. 설정하지 않으면 애플리케이션이 시작되지 않는다. 이 동작(설정이 없으면 열어 두지 않고 막는 것)을 유지한다. 기본값을 넣지 않는다.
- GCS 접근은 코드에 키가 없고 기본 자격 증명(`StorageOptions.getDefaultInstance()`)을 쓴다.

## 민감 데이터
- 저장하는 데이터에 사용자 식별 정보는 없다(영상 제목, 판정, 사람 사유, 내부 이벤트 ID).
- 제목과 검색된 사례의 제목·사람 사유가 Gemini API(외부)로 전송된다. 이벤트에 필드를 추가해 프롬프트나 임베딩에 넣으면 전송 범위가 커지므로, 넣기 전에 사용자에게 확인한다.
- DLQ 전송이 실패하면 이벤트 원문이 에러 로그에 남는다. 이벤트에 민감 필드가 생기면 이 로그 방식을 먼저 바꾼다.

## 깨면 안 되는 경계
1. 모든 관리자 엔드포인트는 `/api/admin/rag/` 아래에 두고 시크릿 필터를 통과하게 한다. 그 밖의 경로에 관리 기능을 열지 않는다.
2. 요청 헤더의 시크릿 값이나 설정의 비밀 값을 로그에 남기지 않는다. 현재 필터는 요청 URI만 로그에 남긴다.
3. 시크릿 미설정 시 기동 실패(fail closed)를 유지한다.
4. 필터의 검사를 약화하거나 특정 경로·환경에서 건너뛰지 않는다.
5. 비밀 값이 필요한 설정은 환경 변수나 설정 키 이름으로만 참조한다.
6. 승격 같은 데이터 변경 기능은 사람 승인 없이 실행되는 경로를 만들지 않는다.

알려진 약점(시크릿 비교 방식, CSV 오류 응답 코드 등)은 `docs/tracking/findings.md`에 있다.
