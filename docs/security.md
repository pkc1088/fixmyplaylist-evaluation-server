### 인증 흐름

- 애플리케이션 기동 시 `evaluation.secret` 설정 여부를 검증한다. 기본값을 두지 않으며, 값이 비어 있거나 누락되면 기동을 중단해 무인증 상태의 실행을 차단한다.
- 외부 요청이 `/api/admin/rag/**` 경로로 진입하면 요청 헤더 `X-Evaluation-Secret`과 `evaluation.secret` 값을 비교한다.
- 값이 일치하면 인증을 통과해 관리자 엔드포인트로 요청을 전달한다.
- 헤더가 누락되었거나 값이 일치하지 않으면 요청을 즉시 거부하고 요청 URI만 로그에 남긴다.
- 정적 공유 시크릿 비교 방식을 사용하며 사용자 계정, 세션, 토큰 만료, 실패 횟수 잠금 정책은 두지 않는다.
- 인증 검사는 특정 경로, 프로파일, 실행 환경에서 약화하거나 건너뛰지 않는다.


### 인가 모델

- 유효한 `X-Evaluation-Secret`을 보유한 호출자: `/api/admin/rag/**` 하위의 모든 관리 기능 실행을 허용한다. 역할별 세부 권한 분리는 두지 않는다.
- 시크릿이 없거나 일치하지 않는 호출자: 모든 관리 기능 접근을 거부한다.
- 금지 규칙: `/api/admin/rag/` 외부 경로에 관리 기능을 열지 않는다. 인증 검사를 우회하는 임시 또는 테스트용 관리자 경로를 추가하지 않는다.
- `/admin-review.html`은 사례 데이터를 포함하지 않는 정적 UI이며 공개 경로다. 데이터 조회와 변경은 모두 `/api/admin/rag/**`에서 시크릿 헤더를 검사한다. 브라우저 화면은 사용자가 입력한 시크릿을 저장소에 기록하지 않고 메모리에서만 사용한다.


### 감사 및 로깅 경계

- 기록 대상: 인증 실패 요청의 URI, DLQ 전송 실패 에러와 해당 이벤트 원문.
- 기록 금지 대상: `X-Evaluation-Secret` 헤더 값, 외부 API 키, DB 비밀번호, 기타 시크릿 설정값.
- 관리자 검수 요청의 `human_reason`은 검수 결과로 MySQL에 저장되고, RAG 평가 시 Gemini로 전송된다. 검수 사유에는 외부 전송이 허용된 정보만 입력한다.
- DLQ 전송 실패 시 이벤트 원문이 에러 로그에 남으므로, 이벤트 스키마에 민감 필드가 추가될 경우 해당 로깅 방식을 먼저 변경한다.


### 자격 증명 관리

- 보관과 주입: `evaluation.secret`, 외부 API 키, DB 및 메시징 자격 증명은 GitHub Secrets에 보관하고 배포 시 Cloud Run 런타임 환경 변수로 주입한다.
- GCS 접근: 정적 서비스 계정 키를 생성하거나 저장하지 않고 런타임 기본 자격 증명을 사용한다.
- 산출물 격리: 소스 코드, 테스트, 설정 예시, 문서, 로그에 실제 비밀 값을 기록하지 않으며 설정 키 이름만 참조한다.
- 수명, 교체, 폐기: 정적 시크릿은 자동 만료되지 않는다. 유출이 의심되거나 교체가 필요하면 GitHub Secrets와 호출자 측 시크릿을 갱신한 뒤 재배포해 기존 값을 폐기한다.


### 민감 데이터 및 외부 전송 정책

- 내부 저장 범위: 사용자 식별 정보는 저장하지 않는다. 저장 대상은 영상 메타데이터, 판정 결과, 사람 검수 사유, 내부 이벤트 ID로 한정한다.
- 외부 전송 범위: 영상 제목과 검색된 참고 사례의 제목 및 사람 검수 사유만 Gemini API로 전송한다.
- 범위 변경 통제: 이벤트에 새 필드를 추가해 임베딩 입력이나 프롬프트에 포함하면 외부 전송 범위가 커지므로, 반영 전 반드시 사전 확인을 거친다.
