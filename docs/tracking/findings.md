### 미해결 문제

- 승격 시 `ReferenceCase` ID 생성 규칙 미확정
    - 조건 및 증상: 승격 기능 설계 시 `EvaluationCase`의 `eventId`를 `ReferenceCase` ID로 재사용할지 별도 ID를 발급할지 정해지지 않아 MySQL 키 설계, 재승격 멱등 처리, Qdrant 결정적 UUID 생성 기준을 확정할 수 없다.
    - 영향 범위: 기준 없이 구현하면 재승격 시 기본 키 충돌이나 Qdrant 포인트 중복이 발생하며, 운영 반영 후 ID 체계를 변경하려면 데이터 마이그레이션과 Qdrant 전체 재색인이 필요하다.
    - 보류 사유: 도메인 키 정책과 운영 데이터 관리 기준에 관한 상위 결정이 필요하다.
    - 접근 방안: `eventId`를 그대로 사용해 1:1 멱등 매핑을 보장하는 방안과 별도 ID 채번 후 원본 `eventId`를 유니크 컬럼으로 유지하는 방안을 비교해 `docs/tracking/decisions/`에 확정한다.
- 유사 사례 검색의 유사도 하한 미적용
    - 조건 및 증상: 기존 참고 사례와 관련성이 낮은 신규 복구 건을 평가할 때도 Qdrant가 점수 하한 없이 상위 5건을 그대로 반환해 Gemini 판정 프롬프트에 주입한다.
    - 영향 범위: 무관한 과거 사례가 판정 근거로 들어가 AI 판정 정확도와 confidence 신뢰도가 저하될 수 있다.
    - 보류 사유: 적정 유사도 임계값 산정에는 누적된 운영 평가 데이터 기반 검증과 검색 파라미터 변경 승인이 필요하다.
    - 접근 방안: `evaluation_cases`의 `retrievedInfo` 유사도 분포와 사람 검수 결과를 대조해 임계값 후보를 검증한 뒤 적용 여부를 결정한다.
